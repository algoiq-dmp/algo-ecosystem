# 25 — Glossary

> **Version:** v3.0.0 | **Owner:** Execution | **Last Updated:** 2026-07-25

## A

**Adapter:** A protocol-specific component within ODIN that translates canonical orders into exchange-specific formats and communicates with exchange gateways or dealer terminals.

**Algo ID:** A unique identifier assigned by SEBI to each algorithmic trading strategy. Must be included in every order routed by ODIN.

## C

**Canonical Order:** The standardized, exchange-agnostic order format used internally by all Lakshmi components.

**Circuit Breaker:** An exchange-mandated trading halt triggered when an instrument's price moves beyond a configured percentage limit (also known as circuit filter).

**Client Order ID:** A unique order identifier generated by the strategy engine. Used for order tracking and deduplication.

## D

**Dealer Terminal:** Third-party trading software (e.g., ODIN Diet, Omnesys Nest) that provides connectivity to exchange trading systems. Used as a fallback path by ODIN.

**Direct API:** Exchange-provided API (e.g., NSE NEAT FIX, BSE BOLT API) that allows direct order routing without a dealer terminal intermediary. Offers lower latency.

## E

**Execution Report:** A message from the exchange confirming an order state change (new, filled, cancelled, rejected). Contains trade details if a fill occurred.

**Exchange Order ID:** The order identifier assigned by the exchange. Used for order modification, cancellation, and trade reconciliation.

## F

**FIX (Financial Information eXchange):** A standard protocol for electronic communication of securities trading information. ODIN uses FIX 4.4 for direct exchange APIs.

**Fill:** The execution of all or part of an order against a counterparty order. Reported via execution reports.

## I

**IOC (Immediate-or-Cancel):** An order type where any unfilled portion is immediately cancelled. Used when partial fills are acceptable but the remainder should not rest in the order book.

## L

**Lot Size:** The minimum tradable quantity for a derivatives instrument. All order quantities must be in multiples of the lot size.

## M

**Multi-Path Routing:** ODIN's ability to route orders through multiple alternative paths (direct API, dealer terminal) for resilience.

## O

**OCO (One-Cancels-Other):** An order linkage where filling one order automatically cancels the other. Used for paired orders in spread strategies.

**Order-to-Trade Ratio:** The ratio of orders placed to trades executed. Monitored by SEBI to detect excessive order activity.

## P

**Price Band:** The upper and lower price limits within which orders can be placed for a given instrument. Also known as circuit filter limits.

**Protocol Translation:** Converting between the Lakshmi canonical order format and exchange-specific protocols (FIX, XML, proprietary binary).

## R

**Reconciliation:** The process of matching ODIN's trade records against exchange-provided trade files to ensure accuracy and completeness.

**RMS (Risk Management System):** The system that validates orders against position limits, margin requirements, and exposure limits. ODIN calls RMS for every pre-trade check.

## S

**SEBI (Securities and Exchange Board of India):** The regulatory authority for securities markets in India. Sets the rules for algorithmic trading compliance.

**Symbol Master:** A reference database containing metadata for all tradable instruments (symbol codes, lot sizes, tick sizes, price bands).

## T

**TIF (Time-in-Force):** A qualifier indicating how long an order remains active. Common values: DAY (until market close), IOC (immediate-or-cancel), GTD (good-till-date).

**Trade File:** An end-of-day file provided by the exchange containing all trades executed for a given trading member. Used for reconciliation.

## V

**Vault:** A secure storage system (HashiCorp Vault, via Suraksha) for managing exchange credentials, API keys, and certificates.
