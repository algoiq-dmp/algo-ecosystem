# 01 -- Overview & Business Objectives

**Version:** 6.3.0 | **Owner:** Execution | **Last Updated:** 2026-08-05

---

## Purpose

**Vega Engine** is the centralized execution engine of the Algo IQ ecosystem. It serves as the bridge between internal trading intelligence and external broker/exchange infrastructure. Every trading signal generated by strategy engines ultimately passes through Vega before reaching the exchange. Vega is responsible for transforming trading decisions into reliable, auditable, and low-latency order execution.

Its architecture is modular, scalable, vendor-independent, and designed for institutional-grade automated trading.

---

## Vega Architecture

The Vega ecosystem consists of three major components:

1. **Vega MAM (Multi Account Manager)**
2. **Talk Strategy API**
3. **Order Processor**

These three components together provide a complete signal-to-order execution framework.

## Key Design Principles

1. **Determinism** -- Every order event is traceable from signal to exchange acknowledgment via Strategy ID
2. **Idempotency** -- Duplicate signals do not create duplicate orders
3. **Fail-safe** -- Multi-tier kill switch is a hard circuit-breaker; no bypass path exists
4. **Broker agnosticism** -- Core order logic is decoupled from broker-specific adapters
5. **Observability** -- Every state transition emits metrics, logs, and audit events
6. **Centralized control** -- One signal can distribute to hundreds/thousands of accounts via MAM

## Constraints

- Must operate within BSE/NSE exchange trading hours (09:15-15:30 IST) for equity segments
- FIX logon/logoff must follow exchange session schedules
- Broker credential rotation must happen without order loss during market hours
- All order modifications and cancellations must propagate through FIX within regulatory TAT
- Maximum 2 concurrent broker connections per user per segment
- Fund allocation rules must be validated pre-trade for every execution
- Strategy ID must be preserved throughout the entire execution lifecycle for audit
