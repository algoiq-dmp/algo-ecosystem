**Version:** 6.3.0
**Owner:** Execution
**Last Updated:** 2026-08-05
**Health SLA:** 99.99%

---

## Overview

Vega Engine is the centralized execution engine of the Algo IQ ecosystem. Every trading signal generated by strategy engines ultimately passes through Vega before reaching the exchange. Its three-component architecture -- **Vega MAM (Multi Account Manager)**, **Talk Strategy API**, and **Order Processor** -- transforms trading decisions into reliable, auditable, low-latency order execution across multiple brokers, accounts, and strategies.

The engine communicates over **FIX protocol**, **REST APIs**, **WebSocket**, and **Message Queues (MQ)** to ensure deterministic order routing with full auditability and sub-millisecond internal latency.

> **See Also:** [Algo IQ Strategy Ecosystem Overview](/knowledgebase/ecosystem-overview.md) -- End-to-end flow from Strategy Factory to Vega Execution.

## Three-Component Architecture

```
[Strategy Engines] --> [Talk Strategy API] --> [Vega MAM] --> [Order Processor] --> [Broker/Exchange]
       |                      |                      |                    |
   Delta, Option,       Signal Validation     Multi-Account Mgmt     Order Lifecycle
   Future, AI,          & Standardization     Fund Allocation        Trade/Position Books
   Manual, External     Strategy Auth         Centralized Risk       Execution Plans
                        Common Identity       Signal Distribution    Kill Switch + Audit
```

### Component #1: Vega MAM (Multi Account Manager)

Manages multiple trading accounts across multiple broker/vendor APIs (XTS, ODIN, REST, FIX, WebSocket). Provides fund allocation (fixed, percentage, margin, risk-based), signal distribution to single/group/basket/portfolio accounts, and centralized pre-trade risk validation.

### Component #2: Talk Strategy API

Standardized communication layer creating a common language for all strategies. Every signal uses a unified format with Strategy ID as the common identity for complete end-to-end traceability from Strategy -> API -> MAM -> Order Processor -> Broker -> Exchange -> Trade -> Position -> Audit.

### Component #3: Order Processor

The execution heart managing full order lifecycle, strategy-wise order books/trade books/net positions, custom execution plans (iceberg, TWAP/VWAP, slippage), multi-tier kill switch, strategy-wise square-off, and complete audit trail from signal to settlement.

## Key Components

| Component | Role |
|---|---|
| **Vega MAM** | Multi-account management, broker connectivity, fund allocation, centralized risk |
| **Talk Strategy API** | Signal standardization, validation, strategy auth, routing engine |
| **Order Processor** | Order lifecycle, books/positions, execution plans, kill switch, audit |
| **XTS Adapter** | FIX 4.4 engine for XTS broker connectivity |
| **ODIN Adapter** | FIX/REST adapter for ODIN API broker connectivity |
| **REST API Adapter** | Generic REST API broker integration |
| **FIX Gateway Adapter** | FIX 4.4/5.0 engine for generic FIX broker connectivity |
| **WebSocket Adapter** | Real-time order streaming to WebSocket brokers |
| **Credential Manager** | Encrypted vault for broker API keys, session tokens, user credentials |
| **Kill Switch System** | Multi-tier emergency control (Strategy/Client/Broker/Exchange/Global) |
| **MQ Bridge** | RabbitMQ producer/consumer for async order communication |
| **Audit Logger** | Immutable order event log for compliance and reconciliation |

## Installation Quick Start

```powershell
# Prerequisites
choco install nodejs-lts rabbitmq redis

# Clone and install
git clone https://github.com/algo-iq/vega.git
cd vega
npm install --production

# Configure
cp config.example.json config.json
# Edit config.json with broker credentials and exchange endpoints

# Initialize database
node scripts/init-db.js

# Start
npm start
```

Verify at `http://localhost:3003/api/v1/health`.

## Risk Controls

| Layer | Mechanism | Threshold |
|---|---|---|
| Layer 1 | Pre-trade validation (Vega MAM) | Symbol, quantity, product, exchange, client permissions |
| Layer 2 | Rate limiting (Talk Strategy API) | Max 500 signals/sec per strategy |
| Layer 3 | Kill Switch (Order Processor) | 1.50% running margin drawdown |

## Signal-to-Trade Traceability

Every order carries the Strategy ID as its common identity:

```
Strategy Signal
   --> Talk Strategy API (validate, authenticate)
     --> Vega MAM (allocate, distribute, transform)
       --> Order Processor (create internal order ID)
         --> Broker Adapter (FIX/REST)
           --> Exchange (exchange order ID)
             --> Trade (trade ID)
               --> Position Update
                 --> Audit Log (Chitragupta)
```
