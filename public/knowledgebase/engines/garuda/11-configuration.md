# 11 — Configuration

## Overview

Garuda Margin Engine uses a layered configuration approach: base `appsettings.json`, environment-specific overrides (`appsettings.{Environment}.json`), environment variables, and external secret management (Azure Key Vault / HashiCorp Vault). All secrets are externalized — never in configuration files or source code.

## Redis Cache TTL Configuration

| Data Type | Key Pattern | TTL | Eviction |
|---|---|---|---|
| Market Price | `price:{exchange}:{symbol}` | 1 second | TTL |
| SPAN Parameters | `span:{exchange}:{underlying}:{date}` | 24 hours | TTL |
| User Session | `session:{broker_id}:{user_id}` | 15 minutes | Sliding |
| Rate Limiter | `ratelimit:{api_key}:{window}` | 1 minute | Fixed window |
| Margin Result | `margin:{client_code}` | 5 minutes | TTL |
| Exchange Config | `config:{exchange}:{broker_id}` | 30 minutes | TTL |
| Client Positions | `positions:{broker_id}:{client_code}` | 30 seconds | TTL |

## Environment-Specific Overrides

### Development
- `Logging.Level`: `Debug`
- `Metrics.Enabled`: `false`
- `HealthCheck.DetailedErrors`: `true`
- `Margin.ReconciliationTolerancePercent`: `0.05`

### Staging / UAT
- `Logging.Level`: `Debug` (Garuda services), `Warning` (framework)
- `Metrics.Enabled`: `true`
- `Tracing.SampleRate`: `0.1`

### Production
- `Logging.Level`: `Warning` (default), `Information` (Garuda)
- `Metrics.Enabled`: `true`
- `Tracing.SampleRate`: `0.05`
- `HealthCheck.DetailedErrors`: `false`
- `Cors.AllowedOrigins`: `["https://dashboard.garuda.dev"]`

## Feature Flags

```json
{
  "featureFlags": {
    "enableHedgeOptimizer": true,
    "enableCryptoMargin": false,
    "enableGraphQL": false,
    "enableWhatsAppAlerts": false,
    "enableNewSpanAlgorithm": true,
    "newSpanRolloutPercentage": 25,
    "hedgeOptimizerRolloutPercentage": 80
  }
}
```

Feature flags are dynamically configurable and do not require service restart. Changes propagate via Redis Pub/Sub within 30 seconds.
